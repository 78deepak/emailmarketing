3. Step-by-Step Implementation Roadmap

Follow this chronological 6-phase sequence to build out the screens in logical dependency order:

Phase 1: Audience & Contacts Management START HERE
Rationale: Without contacts and lists in your database, you cannot send campaigns or test automations.
  • 1. Build Contacts Table (/app/contacts) using TanStack Table with search, status filters, and pagination.
  • 2. Build Add Contact Dialog wired to useCreateContact().
  • 3. Build Import CSV Dialog with drag-and-drop CSV upload calling POST /api/contacts/import.
  • 4. Build Lists View (/app/lists) and list subscriber view.
  • 5. Register routes in routes.tsx for /app/contacts and /app/lists.
Phase 2: Templates & Sender Identities Step 2
Rationale: Every campaign requires an email body template and a verified sender signature.
  • 1. Build Sender Signatures (/app/sending/signatures) to manage "From Name" and "From Email" with verify action.
  • 2. Build Template Gallery (/app/templates) with thumbnail previews, categories, and duplicate action.
  • 3. Build Template Editor (/app/templates/:id/edit) for HTML email content and subject lines.
  • 4. Build Sending Domains (/app/sending/domains) with SPF/DKIM DNS verification instructions.
Phase 3: Campaigns Flow & Analytics Step 3
Rationale: This is the core revenue-generating product functionality of the platform.
  • 1. Build Campaigns List (/app/campaigns) with status badges and action menus (Pause, Resume, Cancel).
  • 2. Build 4-Step Creation Wizard: Campaign Info -> Select List/Segment -> Select Template -> Schedule/Send.
  • 3. Connect schedule API (POST :id/schedule) and recipient resolution (POST :id/resolve-recipients).
  • 4. Build Campaign Analytics Dashboard (/app/campaigns/:id) with open/click rates and delivery timeline chart.
Phase 4: Billing & Upgrades Step 4
Rationale: The trial banner points to /app/billing; users must be able to upgrade before trial ends.
  • 1. Build Billing View (/app/billing) showing current plan quota meters and trial countdown.
  • 2. Render pricing tier cards from GET /api/plans.
  • 3. Wire "Upgrade" button to POST /api/billing/subscription/checkout and load the Razorpay checkout modal.
  • 4. Implement subscription cancellation confirmation dialog.
Phase 5: Lead Forms & Automations Step 5
Rationale: Drip automations and forms leverage your existing contacts, lists, and email templates.
  • 1. Build Forms Manager (/app/forms) with embed code generator and submissions table.
  • 2. Build public form landing page (/public/forms/:formId).
  • 3. Build Automations Workflows (/app/automations) with trigger and step sequence configuration.
  • 4. Add workflow execution run logs.
Phase 6: Workspace Settings, Team & Live Metrics Step 6
Rationale: Completes multi-tenant collaboration and connects live database stats to the home dashboard.
  • 1. Build Profile & Password Settings (/app/settings/profile).
  • 2. Build Team Management (/app/settings/team) for inviting team members and assigning roles.
  • 3. Connect live counts into Home Dashboard Credit Meters (Lists, Campaigns, Subscribers).
  • 4. Populate 7-day send volume and engagement rates.

4. Key Architectural Guidelines

  • Query Invalidation: Follow the convention in use-contacts.ts: root invalidate on create/delete, detail + list invalidate on update.
  • Pagination Envelope: Backend returns { data: T[], meta: { page, limit, total, pages } }. Remember the key is pages, not totalPages.
  • Quota Gating Handling: Backend returns 403 QUOTA_EXCEEDED when tenant exceeds limits. Show a clean "Upgrade Plan" modal rather than a generic error toast.
